# Кеширование проектов

## Описание

Реализовано встроенное кеширование проектов с использованием `@nestjs/cache-manager` для улучшения производительности и удобства работы на фронте.

## Установленные пакеты

- `@nestjs/cache-manager` - встроенный модуль NestJS для кеширования
- `cache-manager` - базовая библиотека для управления кешем (v7.x)
- `keyv` - универсальное хранилище ключ-значение
- `@keyv/redis` - адаптер Redis для Keyv (опционально)

## Архитектура кеширования

### Стратегия кеширования

1. **Кеширование списка проектов (`findAll`)**
   - Кеш-ключи формируются на основе: `userId`, `search`, `institutionId`
   - TTL: 5 минут
   - Список активных ключей сохраняется в кеше для инвалидации

2. **Кеширование отдельного проекта (`findOne`)**
   - Кеш-ключ: `project:{id}`
   - TTL: 5 минут

### Инвалидация кеша

Кеш инвалидируется при следующих операциях:

- **Создание проекта** - очищаются все кеши списков проектов
- **Обновление проекта** - очищаются кеш конкретного проекта и все списки
- **Удаление проекта** - очищаются кеш конкретного проекта и все списки
- **Присоединение участника** - очищаются оба типа кешей
- **Создание приглашения** - очищается кеш проекта
- **Загрузка файлов** - очищается кеш проекта

**Важно**: Список активных ключей кешей списков теперь хранится в самом кеше под ключом `projects:list:keys`, что обеспечивает корректную работу с Redis и несколькими инстансами приложения.

## Использование

### Фронт-енд

Благодаря кешированию:

1. **Быстрые повторные запросы** - список проектов будет возвращён из кеша за ~1-5ms вместо запроса к БД
2. **Уменьшенная нагрузка на БД** - количество запросов к базе существенно снижается
3. **Предсказуемые TTL** - данные в кеше свежие, с максимальной задержкой 5 минут

### Примеры запросов

```bash
# Получение списка проектов (закешировано)
GET /projects

# Получение проектов с поиском (отдельный кеш-ключ)
GET /projects?search=machine%20learning

# Получение проектов по учреждению (отдельный кеш-ключ)
GET /projects?institutionId=1

# Получение конкретного проекта (закешировано)
GET /projects/1
```

## Конфигурация

### app.module.ts

Кеш настраивается динамически с использованием Redis (если указан `REDIS_URL`) или in-memory хранилища:

```typescript
CacheModule.registerAsync({
  isGlobal: true,
  imports: [ConfigModule],
  useFactory: (configService: ConfigService) => {
    const redisUrl = configService.get<string>('REDIS_URL');

    if (redisUrl) {
      // Use Redis
      const redisKeyv = new Keyv({
        store: new KeyvRedis(redisUrl),
        namespace: 'pd-projects',
        ttl: 5 * 60 * 1000,
      });
      return { stores: [redisKeyv] };
    }

    // Fallback to in-memory
    const memoryKeyv = new Keyv({
      namespace: 'pd-projects',
      ttl: 5 * 60 * 1000,
    });
    return { stores: [memoryKeyv] };
  },
  inject: [ConfigService],
})
```

### Настройка Redis

Для использования Redis добавьте переменную окружения:

```bash
REDIS_URL=redis://localhost:6379
```

Если `REDIS_URL` не указан, приложение автоматически использует in-memory кеш.

## Улучшения

### Исправленные проблемы

1. **Fallback на in-memory** - Если Redis недоступен или не настроен, используется in-memory кеш
2. **Namespace** - Все ключи кеша имеют префикс `pd-projects:` для избежания коллизий
3. **Корректная инвалидация** - Список активных ключей теперь хранится в кеше, а не в памяти, что обеспечивает работу с несколькими инстансами
4. **Обработка ошибок** - Добавлены try-catch блоки для предотвращения падения приложения при проблемах с кешем

### Расширение функциональности

#### Кастомная TTL для разных типов

```typescript
// В конкретном методе сервиса
await this.cacheManager.set(cacheKey, data, 10 * 60 * 1000); // 10 минут
```

#### Мониторинг

Для отладки кеширования можно добавить логирование:

```typescript
async findAll(user?: User, search?: string, institutionId?: number) {
  const cacheKey = this.getCacheKey(...);
  
  const cachedProjects = await this.cacheManager.get<Project[]>(cacheKey);
  if (cachedProjects) {
    console.log('✅ Cache hit:', cacheKey);
    return cachedProjects;
  }
  
  console.log('❌ Cache miss:', cacheKey);
  // ... fetch from DB
}
```

## Заметки

- **Production**: Рекомендуется использовать Redis для обмена кешем между инстансами
- **Development**: Можно использовать in-memory кеш для упрощения разработки
- **Инвалидация**: Текущая реализация инвалидирует все списки при изменениях, что может быть избыточно для больших систем
- **Оптимизация**: Для дальнейшей оптимизации можно:
  - Использовать более короткие TTL для списков (1-2 минуты)
  - Реализовать частичную инвалидацию на основе типа изменения
  - Добавить версионирование кеша
